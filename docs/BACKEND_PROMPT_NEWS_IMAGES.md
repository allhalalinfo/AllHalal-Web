# Промпт для Backend AI: картинки в ленте новостей (News / Briefs)

Скопируйте блок ниже и отправьте backend-разработчику / Backend AI.

---

## Задача

Веб-клиент (`allhalal.info`) показывает превью статей из `GET /api/v1/briefs/feed` (и связанных эндпоинтов). Сейчас часто видны **плейсхолдеры**, хотя поле `image_url` иногда заполнено: внешние CDN **блокируют hotlink** или отдают HTML/ошибку, а **одинаковые Pexels** визуально выглядят как «нет фото».

Нужно улучшить **качество и надёжность поля `image_url`** на стороне API, чтобы web мог стабильно показывать превью.

## Требования к Backend

### 1. Приоритет источника картинки (по убыванию)

1. **URL изображения из RSS/Atom** (`enclosure`, `media:content`, `media:thumbnail`, и т.д.), если это реальный `image/*` URL.
2. Если в RSS нет картинки — **распарсить HTML статьи** и взять:
   - `<meta property="og:image" content="...">`
   - запасной вариант: `<meta name="twitter:image" content="...">`
3. Только если п.1–2 не дали результата — **fallback** (Pexels / внутренний сток), с **разными** photo id / тематическими запросами, **не один и тот же** URL на десятки статей.

### 2. Нормализация URL

- В ответе API отдавать **абсолютный HTTPS URL** где возможно.
- **Дедупликация**: не отдавать один и тот же `image_url` десяткам разных brief id без необходимости.
- Логировать (внутренне) случаи, когда итоговый URL даёт **не** `image/*` при HEAD/GET (чтобы чистить пайплайн).

### 3. Кэш и производительность

- Кэшировать результат **og:image / scrape** по URL статьи (TTL 12–24 ч), не скрейпить синхронно на каждый запрос ленты, если это убивает latency.
- Таймаут на внешний fetch (например 5–8 с) и **graceful fallback** на Pexels только после таймаута/ошибки.

### 4. Контракт API (без ломания клиента)

- Поле **`image_url`** остаётся строкой или `null`.
- По возможности добавить опциональные поля (если готовы версионировать API):
  - `image_source`: `"rss" | "og" | "fallback"`
  - `image_fetched_at`: ISO8601  
  Старые клиенты их игнорируют.

### 5. Критерий готовности

- В выборке из 30 элементов `/api/v1/briefs/feed` **не более 30–40%** записей с **одинаковым** `image_url` (кроме явного fallback-каталога).
- Для топ-источников без картинок в RSS (About Islam, MuslimMatters, Islam21c и т.д.) **≥70%** записей имеют **уникальное** превью, совпадающее с реальной статьёй (og:image).

## Контекст для Web (кратко)

Фронт грузит превью через **собственный прокси** `/api/image-proxy` и fallback на прямой URL. Если upstream отдаёт **403/HTML/JSON** вместо картинки, в UI останется плейсхолдер. Поэтому **стабильные, прямые image URL** с вашей стороны критичны.
